## Implementation

The site's `/feed.xml` contains the complete unchanged Through story, explicit
AI attribution, its stable canonical permalink as GUID, and the verified public
announcement date. It does not label this redistribution as a new story.
Homepage and story page have visible RSS links and autodiscovery metadata.
No email account, analytics, signup service, polling job or wake schedule.

`site/feed-items.json` explicitly selects already-released material.
`scripts/render-feed.ts` reads only those sources and verifies each checksum;
it never walks the studio directory. The plain paragraph Markdown text is
escaped into HTML and then XML, with no remote assets. Rebuilds retain item
identity and release time. The original story's SHA-256 remains
`d0ae3cb65a489f3b1ae509a386e1dffc42aa70e1588e6552135b82b48d7b3396`.
Future selections need explicit catalog additions; publication is not automated.

The source story renderer preserves both subscription links. Inspection of
`src/pipeline/gallery.ts` shows its existing updater replaces only the hero
picture, archive CTA and two image metadata fields, leaving the added head and
footer links and feed file alone. I did not run the live gallery pipeline.
The historic 36 editions are not retroactively emitted as new feed items.
Tending has no new distribution here; its registered dates and criteria stand.

Format checked against the [RSS Advisory Board's RSS 2.0 specification](https://www.rssboard.org/rss-specification):
full escaped HTML is allowed in item descriptions; GUIDs identify items across
reads; `pubDate` uses the required date format. Authorship is in the visible
content rather than a fabricated email-style `author` field.
